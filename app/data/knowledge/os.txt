# 操作系统
@操作系统基础
10|（一）操作系统的基本概念|操作系统职责与特征|操作系统为用户和硬件分别做什么？并发与并行有何区别？|管理处理机、内存、文件和设备，提供程序执行环境和服务接口；并发是时间段内交替推进，并行是同一时刻实际同时执行；共享、虚拟、异步也是典型特征|单核也能并发，异步指进程推进速度不可预知而非一定并行。
10|（二）操作系统发展历程|批处理、分时和实时|三类系统各优先满足什么目标？|批处理追求吞吐与资源利用；分时通过时间片为多用户提供交互响应；实时强调在规定期限内响应，硬实时超期可能不可接受|响应快不自动构成实时系统，关键是时间约束与可预测性。
10|（三）1.CPU运行模式|内核态与用户态|特权指令为何不能由普通应用任意执行？如何从用户态进入内核态？|特权操作可影响系统和其他进程，需保护；系统调用、异常或中断通过受控入口进入内核态；返回用户态要恢复适当状态|普通函数调用本身不切换特权级，切到内核态也不必切进程。
10|（三）2.中断和异常的处理|异常处理与进程|应用缺页后操作系统如何处理？|保存现场，检查访问合法性；合法但缺页则分配页框、必要时换出、读取页面、更新页表和 TLB；阻塞期间可调度其他进程；完成后重执行原指令|非法地址通常不能靠调页解决，应按保护错误处理。
10|（三）3.系统调用|系统调用与库函数|read() 之类库接口与系统调用有什么关系？|库接口可能封装系统调用，通过陷入指令把参数和调用号交给内核；内核验证后执行受保护服务并返回；有些库函数完全在用户态执行|库函数名相同不意味着每次调用都必然陷入内核。
10|（三）4.程序的链接与装入|链接和装入方式|静态链接、装入时动态链接、运行时动态链接怎样区分？逻辑地址何时重定位？|静态链接在运行前合并目标模块；装入时动态链接在装入时解析共享库；运行时动态链接在需要时解析；重定位可在装入时完成，也可由硬件在执行时动态完成|共享库可以共享只读代码页，进程的可写数据通常分别管理。
11|（三）5.程序运行时的内存映像与地址空间|进程内存映像|进程地址空间中的代码、数据、BSS、堆、栈一般各存什么？|代码区存指令；数据区存已初始化静态数据；BSS 表示零初始化静态存储；堆用于动态分配；栈保存调用相关数据；具体布局依系统与 ABI|虚拟地址连续不保证对应物理页连续；栈增长方向不是跨平台定律。
11|（四）操作系统结构|分层、模块化、宏内核、微内核、外核|这五种结构的组织思路分别是什么？|分层限制层间依赖；模块化按接口组合部件；宏内核把多类服务放内核；微内核仅保留少量核心机制，其他服务移至用户态；外核侧重安全分配硬件资源，把较多抽象交给库|微内核不等于完全没有驱动或通信开销；结构可混合。
11|（五）操作系统引导|系统启动过程|从上电到用户程序可运行，典型启动链是什么？|固件完成必要初始化并选择启动项；引导程序加载内核及必要信息；内核初始化内存、设备和调度；启动首个用户态进程与服务|固件、引导程序和内核是不同阶段，不必限定为某一种 BIOS 实现。
11|（六）虚拟机|虚拟机与进程隔离|系统虚拟机如何运行客户操作系统？虚拟机监控器做什么？|监控器提供虚拟 CPU、内存和设备，管理多个客户系统的资源与隔离；特权行为由陷入模拟或硬件虚拟化支持；客户系统看到受控硬件抽象|虚拟机和普通进程/容器不是同一抽象层，容器通常共享宿主内核。
@进程管理
11|（一）1.进程与线程的基本概念|进程与线程|为什么进程是资源分配单位而线程通常是调度单位？|进程拥有地址空间等资源；同一进程的线程共享代码、数据、打开文件等，各自有寄存器、PC 和栈；线程切换可更轻，但共享数据需同步|线程并非共享一切，线程栈和执行现场独立。
11|（一）2.进程/线程的状态与转换|就绪、运行、阻塞|等待 I/O 完成的进程为何不在就绪队列？阻塞到运行通常经过什么？|阻塞进程缺少 CPU 以外的条件，给 CPU 也不能继续；I/O 完成使其就绪，之后经调度进入运行；时间片用尽使运行转就绪|就绪到阻塞通常不会直接发生，需先运行并请求等待。
11|（一）3.线程的实现|内核线程与用户线程|纯用户级线程的一个阻塞系统调用可能有什么影响？|内核不了解用户库中的多个线程时，一个内核执行实体阻塞会影响映射到它的用户线程；内核级线程由内核独立调度，可利用多核；多对多模型折中|“用户线程必不能并行”只对多用户线程映射单内核线程等特定模型成立。
11|（一）4.进程与线程的组织与控制|PCB 与控制操作|PCB 保存哪些内容？创建、撤销、阻塞、唤醒需要更新什么？|保存标识、状态、寄存器现场、调度信息、内存及资源引用等；控制操作要原子地修改状态及相应队列，创建分配资源，撤销回收资源|PCB 是进程存在的管理依据，不能只改状态而忘记队列链接。
11|（一）5.进程间通信：共享内存、消息、管道、信号|四种 IPC|共享内存、消息传递、管道、信号各适合传什么？|共享内存直接共享区域，需自行同步；消息传递按消息发送接收；管道为有序字节流，常用于进程间数据连接；信号用于异步通知事件，携带数据能力有限|共享内存减少复制但不会自动消除竞态；管道不保证应用层消息边界。
11|（二）1.调度的基本概念|三级调度|作业调度、中级调度、进程调度分别选择什么？|作业调度决定哪些作业进入内存参与执行；中级调度决定挂起与恢复以控制内存负载；进程调度从就绪者中选择占用 CPU 的实体|并非每种操作系统都显式实现全部三级。
11|（二）2.调度的目标|周转与响应短计算|作业到达 0、首次运行 3、结束 10、总 CPU 服务 4，周转、带权周转、响应时间多少？|周转=10-0=10；带权周转=10/4=2.5；响应=3-0=3；等待时间是就绪队列中的累计等待，需与 I/O 阻塞区分|有 I/O 时不能简单把全部非运行时间都算成就绪等待。
11|（二）3.调度的实现|抢占、调度时机与闲进程|抢占与非抢占如何区分？没有就绪任务时怎么办？|抢占允许任务仍可运行时因时间片或优先级被夺走 CPU；非抢占通常等阻塞或结束才让出；调度器维护就绪队列并选择任务，闲进程承担无普通就绪任务时的执行|中断到来不一定立刻调度；内核临界区等情形可能暂时禁止抢占。
11|（二）3.内核级线程与用户级线程调度|两级线程调度|用户线程库与内核分别看到什么调度对象？|用户线程库选择用户线程在其内核线程上运行；内核调度内核可见线程到 CPU；映射模型决定并行度、阻塞影响和上下文切换成本|内核无法直接调度对它不可见的用户线程。
11|（二）4.CPU调度算法|FCFS、SJF 与 SRTF|三者选谁执行，各有哪些典型问题？|FCFS 按到达先后，可能护航效应；SJF 选预计服务时间短者；SRTF 为抢占式，选剩余时间最短者；短任务优先可能使长任务饥饿|需要说明是否可抢占以及是否知道或预测服务时间。
11|（二）4.CPU调度算法|高响应比、优先级与时间片|HRRN 响应比怎么求？时间片过大或过小有什么后果？|响应比=(等待时间+服务时间)/服务时间，选最高者；优先级调度可用老化防饥饿；RR 时间片太大趋于 FCFS，太小则切换开销大；多级反馈队列按行为调整队列|高响应比优先通常非抢占，别把响应比当响应时间。
11|（二）4.CPU调度算法|SRTF 短推演|A 到达0需5，B 到达1需2，忽略切换开销，SRTF 完成时间各多少？|0～1 A 执行剩4；1～3 B 执行完；3～7 A 完成；完成时间 A=7、B=3；周转分别7、2|新任务只在剩余时间更短等满足策略条件时抢占。
11|（二）5.多处理机调度|多核调度权衡|负载均衡与处理器亲和性为何可能冲突？|迁移任务可让各核负载接近，但会损失缓存、TLB 等局部性；亲和性尽量让任务留在熟悉核心；共享队列或每核队列需要不同的协调方式|只看任务数量不一定等于负载相同，还要看运行需求。
12|（二）6.上下文及其切换机制|上下文切换|进程切换需保存/恢复什么？与模式切换有何不同？|保存恢复寄存器、PC、栈指针、状态及必要内核调度状态；地址空间切换可能影响页表与 TLB；模式切换仅改变特权状态，可仍为同一进程|系统调用不必导致进程切换，切换本身产生开销。
12|（三）1.同步与互斥的基本概念|同步互斥与临界区|同步和互斥分别约束什么？临界区解决方案应满足什么？|互斥保证同一临界资源同时最多一个访问者；同步规定执行先后关系；常见要求包括空闲让进、忙则等待、有限等待、让权等待|忙等待锁在特定场景有用，但不满足“等待时让出 CPU”的要求。
12|（三）2.基本实现方法：软件方法|Peterson 算法|两进程 Peterson 算法为何同时需要 flag 和 turn？|flag 表示访问意愿，turn 在双方同时有意愿时让一方先行；在读写原子且满足相应内存顺序模型时可实现两进程互斥；进入前设自己的 flag，再让 turn 指向对方|现代编译器和 CPU 可能重排，实际实现需原子操作/内存屏障，不能直接用普通变量保证正确。
12|（三）2.基本实现方法：硬件方法|关中断与原子指令|关中断、Test-and-Set、Compare-and-Swap 的适用限制是什么？|关本核中断只约束本核，不能单独解决多核互斥；原子交换或 CAS 对共享位置不可分割地读改写，可构造锁；常须配合内存顺序保证|原子指令能做锁，不保证自动公平或无饥饿。
12|（三）3.锁|自旋锁与阻塞锁|什么情况下倾向自旋锁，什么情况下倾向阻塞锁？|临界区短且持锁者可在别核很快释放时自旋可避免调度开销；等待较长时阻塞让出 CPU；使用锁要保持一致顺序并及时释放|单核上持锁者不能运行时自旋可能无意义；持自旋锁时通常不能执行可能睡眠的操作。
12|（三）4.信号量|P/V 语义|记录型信号量 P、V 的逻辑是什么？初值如何表达资源数？|P 原子地减1，若值<0 则阻塞；V 原子地加1，若值≤0 则唤醒一个等待者；初值可表示可用资源数量；互斥量常初值1|负值绝对值在该模型中表示等待数，不表示负的物理资源。
12|（三）5.条件变量|条件变量等待|为何条件变量 wait 常写在 while 循环内？等待是否释放锁？|wait 原子地释放关联锁并阻塞，返回前重新持锁；唤醒后条件可能已被其他线程改变，也可能虚假唤醒，故 while 重新检查；signal 通知等待者但不代替条件状态|条件变量通知通常不积累成可消费的许可，与信号量不同。
12|（三）6.经典同步问题：生产者—消费者|有界缓冲区 P/V|容量 N 的生产者消费者，empty、full、mutex 初值与生产者顺序是什么？|empty=N、full=0、mutex=1；生产者 P(empty)、P(mutex)、放入、V(mutex)、V(full)；消费者对称为 P(full)、P(mutex)、取出、V(mutex)、V(empty)|若先持 mutex 再等待 empty/full，可能阻止对方创造所需条件而死锁。
12|（三）6.经典同步问题：读者—写者|读写同步|读者优先方案如何允许多个读者？可能有什么公平性问题？|读者计数受互斥锁保护，第一个读者锁定共享资源，最后一个读者释放；写者独占资源；持续到来的读者可使写者饥饿|“无互斥错误”不代表“无饥饿”，需区分读者优先、写者优先和公平方案。
12|（三）6.经典同步问题：哲学家进餐|哲学家死锁|所有人先拿左筷再拿右筷为何可能死锁？给出一种解决方法。|每人持有一根且等待下一根，形成循环等待；可统一按筷子编号从小到大获取，破坏循环等待；也可限制同时尝试人数等|仅随机延时不能提供确定的无死锁保证。
12|（四）1.死锁的基本概念|死锁四条件|死锁的四个必要条件是什么？与饥饿有何区别？|互斥、占有且等待、不可剥夺、循环等待；死锁是一组进程相互等待无法推进；饥饿可能是某进程长期不获资源而其他进程仍推进|资源分配图有环在每类资源单实例时可判死锁，多实例时不充分。
12|（四）2.死锁预防|破坏死锁条件|一次申请全部资源、按序申请、允许抢占分别破坏什么条件？|分别破坏占有且等待、循环等待、不可剥夺；预防通过制度使必要条件不能全部成立，可能降低利用率或灵活性|互斥常由资源性质决定，不能随意取消。
12|（四）3.死锁避免|银行家算法安全性|Available=1，P1 Need=1 Allocation=1，P2 Need=2 Allocation=1，安全吗？|可先满足 P1，完成释放其1个已分配资源，Work变2，再满足P2；安全序列 P1、P2；一般逐个寻找 Need≤Work 的进程并假设完成释放 Allocation|不安全不等于已经死锁；请求还需满足 Request≤Need 且≤Available，再试分配检查。
12|（四）4.死锁检测和解除|检测与解除|系统允许死锁发生时，如何发现和解除？|检测可用等待图或基于现有请求/可用资源的化简算法；解除可终止部分进程、抢占资源并回滚；选择牺牲者时考虑代价和公平性|检测使用当前等待请求，避免算法通常还需要未来最大需求。
@内存管理
12|（一）1.内存管理的基本概念|地址空间、共享与保护|逻辑地址与物理地址如何隔离进程？共享内存怎样同时存在？|每个进程有自己的地址转换与权限；相同虚拟地址可映射不同页框；共享可让不同进程的若干虚页映射同一页框，仍按权限控制访问|共享页不意味着整个地址空间都共享，也不自动保证同步。
12|（一）1.内存分配与回收|分配与回收|内存分配器需要维护什么？回收时为何合并相邻空闲区？|维护空闲区或空闲页框及占用信息；分配需满足大小、对齐与策略；回收标记空闲，连续分区合并物理相邻空闲区可减少外部碎片|两个地址不相邻的空闲区不能直接合并成连续区。
12|（一）2.连续分配管理方式|连续分配与碎片|固定分区、可变分区主要产生哪种碎片？首次、最佳、最坏适应怎样选？|固定分区主要内部碎片，可变分区主要外部碎片；首次选首个足够区，最佳选最小足够区，最坏选最大区；紧凑需支持重定位|最佳适应未必长期表现最佳，可能产生许多小洞。
12|（一）3.页式管理|分页与多级页表|分页为何避免外部碎片？多级页表节省什么？|页与页框大小固定，进程可占离散页框，最后一页可能内部碎片；多级页表仅为实际使用的虚拟地址范围分配下级页表，减少稀疏空间的页表占用|多级页表通常增加无 TLB 命中时的查表次数。
13|（一）4.段式管理|分段与分页比较|分段为什么方便共享保护，又可能产生外部碎片？|段对应代码、数据等逻辑单元，可分别设权限与共享；段长可变，通常需连续空间，分配回收形成外部碎片；页则是固定大小的物理管理单位|页号/页内偏移通常由硬件按地址位划分，段结构更体现逻辑组织。
13|（一）5.段页式管理|段页式管理步骤|段页式如何兼顾逻辑分段与离散分配？|程序按段组织，每段再分页；段表定位各段页表，页表指向可离散放置的页框；按段检查界限/权限，按页调入与分配|普通无 TLB 情况下可能先访段表、再访页表、再访数据，不能少算。
13|（二）1.虚拟内存的基本概念|虚拟内存特征|为何程序不必全部装入就能执行？限制是什么？|利用局部性，只装入当前需要部分，缺失时按需调入；表现为多次性、对换性和虚拟性；地址空间受体系结构限制，实际可承诺容量还受内存与后备存储约束|虚拟内存不等于无限内存，严重缺页会显著变慢。
13|（二）2.请求页式管理|缺页处理与页表位|有效/存在位、修改位、访问位分别有何用途？|存在位指示是否驻留主存；修改位决定换出是否需写回；访问位记录近期访问，供置换参考；缺页处理要验证合法性再装入并更新映射|页不存在与地址无效不同；题目中“有效位”含义须结合定义。
13|（二）3.页框分配与回收|驻留集与置换范围|固定/可变分配、局部/全局置换分别描述什么？|分配描述每进程可用页框数是否变化；局部置换只从本进程驻留页中选牺牲页，全局可从其他进程页中选；需平衡进程需求和系统负载|分配策略与置换算法是不同维度，不能混为一谈。
13|（二）4.页置换算法|OPT、FIFO、LRU 与 Clock|四种策略各淘汰哪一页？哪种可能有 Belady 异常？|OPT 淘汰未来最晚再访问者，仅作理想比较；FIFO 淘汰最早进入者，可能 Belady 异常；LRU 淘汰最久未访问者；Clock 通过访问位循环寻找候选|精确 LRU 代价高，Clock 是近似策略，不等同于 FIFO。
13|（二）4.页置换算法|页面置换短推演|3 个空页框，访问 1,2,3,1,4,1，FIFO 与 LRU 各缺页几次？|前三次都缺页，第4次命中；FIFO 第5次淘汰1，第6次又缺，共5次；LRU 第5次淘汰2，第6次1命中，共4次|命中会更新 LRU 最近使用次序，但不会改变 FIFO 入队次序。
13|（二）5.内存映射文件|mmap|内存映射文件如何把文件 I/O 转为内存访问？|将文件区间映射到虚拟页，缺页时由系统从文件读入；修改是否回写依共享/私有映射等语义；可减少显式复制并便于共享|映射成功不意味着整个文件立即读入内存；私有写时复制不等于直接改原文件。
13|（二）6.虚拟存储器性能的影响因素及改进方法|抖动与工作集|抖动是什么？如何根据工作集或缺页率缓解？|进程所需活跃页面多于可用页框时频繁换入换出；工作集估计近期活跃页集合；可增加页框、降低并发度、改进局部性或按缺页率调节分配|抖动时单纯提高 CPU 多道程度可能进一步恶化。
@文件管理
13|（一）1.文件的基本概念|文件与访问方式|文件是什么抽象？顺序访问与直接访问有何区别？|文件是命名的持久信息集合；顺序访问按当前位置推进，直接访问可按偏移或记录号定位；系统维护类型、大小、权限等属性|文件逻辑组织不等于物理磁盘块分配方式。
13|（一）2.文件元数据和索引节点|inode 与目录项|inode 存什么？文件名通常在哪里？|inode 保存类型、权限、属主、大小、块索引和链接数等元数据；目录项通常建立名字到 inode 的映射；多个名字可指向同一 inode|不能把文件名一般性地认为存放在 inode 内。
13|（一）3.文件的操作|建立删除打开关闭读写|open 与 read 各做什么？删除已打开文件一定立即释放数据吗？|open 解析路径并建立打开文件状态，read 根据文件位置与权限读数据并更新偏移；close 释放打开引用；创建分配元数据，写更新内容；类 Unix 删除解除名字，链接数和打开引用均消失后才可回收|文件描述符、系统打开表和 inode 是不同层次。
13|（一）4.文件的保护|权限与访问控制|访问控制表与能力表各以谁为中心？|ACL 以对象为中心列出用户/主体权限；能力表以主体为中心列出可访问对象及权限；常见读写执行权限限制操作|口令、加密与访问控制解决的问题不同，文件加密不取代权限检查。
13|（一）5.文件的逻辑结构|流式与记录式文件|无结构文件与有结构文件怎样区分？|无结构通常为字节流，应用解释内容；有结构由记录组成，可定长或变长，并可采用顺序、索引等逻辑组织|“无结构”指操作系统不解释记录结构，不代表内容没有意义。
13|（一）6.文件的物理结构|连续、链接和索引分配|三种磁盘块分配的随机访问和扩展性如何？|连续分配随机访问快但扩展困难且有外部碎片；链接分配易扩展但链式随机访问差；索引分配通过索引块定位，随机访问较好但有索引开销；FAT 把链指针集中保存|文件逻辑连续不要求磁盘物理连续。
13|（一）6.文件的物理结构|多级索引容量短计算|块 4 KiB，索引项4 B，仅一个二级间接入口最多指向多少数据？|一块容纳1024项，二级共1024²个数据块；数据容量=1024²×4096 B=4 GiB；不含索引块自身占用|题目若还给直接和一级入口，应分别累加；注意 GiB 与 GB。
13|（二）1.目录的基本概念|目录与路径解析|目录管理的核心映射是什么？路径访问如何逐级进行？|把名字映射到文件元数据标识；从根或当前目录开始逐个查找路径分量，检查相应目录访问权限；目录也是需存储管理的对象|拥有文件读取权限不一定意味着有权穿越其所有父目录。
13|（二）2.树形目录|绝对与相对路径|绝对路径、相对路径、当前目录各是什么意思？|绝对路径从根开始；相对路径以当前工作目录为起点；树形目录允许不同目录中使用相同文件名，路径用于区分|同名文件不一定是同一个对象；路径字符串与对象标识不同。
13|（二）3.目录的操作|目录操作|创建、删除、查找和重命名目录项时要保持什么一致性？|保持名字到对象的映射、链接计数和父子关系正确；删除目录通常要求为空或显式递归处理；重命名需按文件系统规则原子更新相关目录项|删除目录项不必等于立即销毁文件内容。
14|（二）4.硬链接和软链接|硬链接与符号链接|删除原名后，两种链接怎样表现？能否一般性跨文件系统？|硬链接指向同一 inode，原名删除后其他硬链接仍可访问，通常不能跨文件系统；软链接保存路径，可跨文件系统，目标路径消失会悬空|硬链接不是文件副本；软链接有自己的对象和权限处理规则。
14|（三）1.文件系统的全局结构|磁盘与内存中的文件系统结构|文件系统在外存和内存中通常分别维护什么？|外存有超级块/卷控制信息、目录、文件控制块或 inode、数据块和空闲信息；内存有挂载信息、缓存、打开文件表和进程文件描述符表|进程的文件偏移与磁盘 inode 中的持久元数据不要混淆。
14|（三）2.外存空闲空间管理方法|空闲块管理|位图、空闲链表、成组链接各如何记录空闲块？|位图用每块一位表示占用，可寻找连续空闲区；链表串联空闲块；成组链接在部分空闲块中存一组空闲块号并链接下一组|位图中0或1代表空闲取决于约定，计算容量前应确认。
14|（三）3.虚拟文件系统|VFS|VFS 如何让同一 read 接口支持不同文件系统？|定义统一对象和操作接口，由具体文件系统实现对应方法；路径解析和文件操作通过抽象层分派；屏蔽部分底层格式差异|VFS 是接口抽象，不是另一种磁盘数据格式。
14|（三）4.文件系统挂载|挂载点|挂载文件系统是什么意思？卸载前为何检查打开引用和脏缓存？|把一个文件系统根接到现有目录树的挂载点，路径解析可进入该系统；卸载需确保活动引用允许卸载并处理未落盘数据|挂载不会简单把全部文件复制到挂载目录。
@输入／输出管理
14|（一）1.设备：概念、分类、I/O接口和端口|设备与接口|块设备、字符设备与设备端口有何区别？|块设备通常按块寻址并支持随机访问，如磁盘；字符设备通常以字符流方式访问；控制器接口通过数据、状态和控制寄存器与 CPU 交互，寄存器地址形成端口|分类是接口语义，不完全由硬件传输时一次发送几个字节决定。
14|（一）2.I/O控制方式|轮询、中断与 DMA|这三种方式下 CPU 的参与程度如何变化？|轮询由 CPU 反复查状态并搬数据；中断让设备就绪后通知 CPU，仍可能由 CPU 搬数据；DMA 由控制器直接在设备与内存间批量传输，CPU 初始化并处理完成|采用 DMA 的设备仍可用中断通知完成。
14|（一）3.I/O软件层次结构|I/O 软件分层|用户 I/O 软件、设备独立软件、驱动、中断处理各做什么？|用户层提供库和格式化等；独立层提供命名、保护、缓冲等通用服务；驱动把请求转为设备命令；中断处理响应硬件事件并推进完成流程|设备驱动负责具体设备，不应让普通应用直接执行特权 I/O。
14|（一）4.输入输出应用程序接口|字符、块、网络与阻塞接口|阻塞与非阻塞调用的返回行为如何区分？|字符接口面向流，块接口可按块访问，网络常通过套接字；阻塞调用条件未满足时让线程等待；非阻塞立即返回现有结果或未就绪状态|非阻塞不等于异步完成通知；阻塞线程不一定让整个系统停住。
14|（二）1.缓冲区管理|单缓冲与双缓冲|双缓冲为什么可提高连续 I/O 效率？|一个缓冲由设备填充时，另一个可供 CPU 处理，形成重叠；吞吐受设备、复制和计算中最慢环节限制；缓冲池可供多个请求共享|不能忽略用户区复制时间，具体时间题须画出并行/互斥阶段。
14|（二）2.设备分配与回收|设备分配|独占、共享、虚拟设备的分配策略有何不同？|独占设备同一时段分给一个使用者，共享设备可交错服务多个请求；虚拟设备通过软件把独占资源变成逻辑共享；分配时检查权限、可用性及死锁风险，结束后回收|逻辑共享不表示物理设备能同时执行所有请求。
14|（二）3.假脱机技术（SPOOLing）|SPOOLing|打印任务怎样通过 SPOOLing 让多个进程提交？|把任务写入磁盘上的输入/输出井或队列，由后台服务按序送到物理设备；用户面对逻辑设备，物理打印机仍串行服务|假脱机依赖缓冲与后台调度，不是要求用户手动离线传送介质。
14|（二）4.设备驱动程序接口|驱动接口|统一驱动接口通常向上提供什么，向下隐藏什么？|向上提供打开、关闭、读写、控制等约定入口与完成状态；向下封装设备寄存器、命令、DMA、中断等细节；请求可能异步完成|驱动入口返回与设备实际完成可能不是同一时刻。
15|（三）1.磁盘：结构、格式化、分区|磁盘组织|低级格式化、分区、逻辑格式化分别建立什么？|低级格式化组织物理扇区等底层结构；分区划分逻辑区域；逻辑格式化在分区上建立文件系统元数据；现代磁盘低级格式化通常由厂商完成|建立分区不等于已经建立可存文件的文件系统。
15|（三）1.磁盘调度方法|磁盘调度策略|FCFS、SSTF、SCAN、C-SCAN、LOOK 的区别是什么？|FCFS 按到达；SSTF 选最近磁道可能饥饿；SCAN 到端点再折返；C-SCAN 单向服务后回到另一端；LOOK 只到该方向最远请求再折返|移动方向、盘边界、回程是否计时必须按题意明确。
15|（三）1.磁盘调度方法|磁盘移动短计算|磁头在50，请求10、60、20，按SSTF总移动多少？|先60移动10，再20移动40，最后10移动10，总60；只计算磁道距离，不含旋转和传输时间|不能把原请求次序当作 SSTF 执行次序。
15|（三）2.固态硬盘：读写性能、磨损均衡|SSD 管理|磨损均衡与垃圾回收分别解决什么问题？|磨损均衡把擦写分散到不同块，避免少数块过早失效；垃圾回收搬迁有效页、擦除可回收块；控制器的地址映射支持异地更新|垃圾回收和写放大可使写延迟波动，不能用机械寻道算法直接解释 SSD 性能。
